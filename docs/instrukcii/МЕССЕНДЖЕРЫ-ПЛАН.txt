SongForge — MAX / VK: актуально на 10.09.2026
==============================================
MAX-воронка в коде (2.11.55). VK и напоминания — не пилим, пока не скажете.
Источники: dev.max.ru, dev.vk.com, 152-ФЗ, 38-ФЗ.

Решение коротко
---------------
Не три студии. Один человек в одной карточке.
Бот в MAX/VK — продажник + память. Сайт — студия, оплата, помощник.
Первый экран — согласия (как у нормальных ботов вокруг).
Дальше диалог, пока человек сам не «Стоп» / не заблокирует.
Связка с сайтом — через идентификаторы, не «два разных чата».


1. Что требуют платформы (не догадки)
-------------------------------------

MAX (официально, 2026)
  Подключение: юрлицо / ИП / самозанятый РФ. У нас ИП — ок.
  Кабинет: business.max.ru, верификация через Госуслуги.
  API: только platform-api2.max.ru (с 19.07.2026).
  Бот без мини-приложения можно. Мини-приложение — только через бота.
  Диплинк: https://max.ru/<bot>?start=<payload>  (до 128 символов)
  Событие bot_started: user_id, имя, payload.
  Кнопки: callback и link (ссылка на сайт).

  Юр. до первого использования (типовое соглашение MAX, п.3.1):
    пользователь ОБЯЗАН увидеть сведения о нас, политику ПД
    и условия использования. Иначе не запускать.
  В боте/мини-аппе: соглашение, политика, реквизиты, поддержка.
  Массовые рекламные рассылки Bot API — только если есть договор
  с MAX (требования п.1.5). Без договора: пишем в уже начатый диалог,
  не «базой на 10 тысяч».

VK
  Бот = сообщения сообщества. Писать первым холодным нельзя:
  человек сам пишет / жмёт «Начать».
  Рекламная рассылка: явное согласие, не чаще 1 раза в 7 дней,
  кнопка отписки, intent promo_newsletter.
  Нельзя делать «работа бота только после подписки на паблик».
  Бот не должен ТОЛЬКО гонять на чужой сайт (п.5) — сначала польза
  в чате (собрали идею, ответили), потом студия.

Закон РФ (и сайт, и бот)
  152-ФЗ — согласие на обработку ПД, политика, можно отозвать.
  38-ФЗ — отдельное согласие на РЕКЛАМУ. «Пользуюсь ботом» ≠ реклама.
  Оферта — про оплату нот (у нас уже /legal/offer).
  На сайте при входе уже: соглашение + политика + согласие на ПД.
  Согласия на рассылку на сайте пока НЕТ — в боте его как раз и берём.


2. Первый экран — не четыре документа, одна кнопка
--------------------------------------------------
Тексты НЕ копируем в чат. Они уже на сайте:
  /legal/terms   соглашение
  /legal/privacy политика (внутри — согласие на ПД)
  /legal/offer   оферта — это про ОПЛАТУ, не про вход

На сайте при входе одна галочка: соглашение + политика + ПД.
Оферту при входе не спрашиваем — она при оплате. В боте так же.

Если первое касание — БОТ:
  уже берём MAX id, имя, переписку. Ждать галочку на сайте нельзя.
  Регистрация здесь: одно «Принимаю» = те же три пункта, что на сайте,
  плюс в том же тексте — сообщения в этот чат.
  Ссылки ведут на те же страницы сайта.

  «Есть слова, которые вслух не выходят. Их как раз кладут в песню.
   Сейчас набросаем — кому и про что. Через минут пять два варианта.
   Первая проба бесплатно.
   «Поехали» — как галочка на сайте: соглашение, политика и редкие
   сообщения сюда. Стоп — напишите «стоп».»

  Ссылки: Соглашение · Политика
  Кнопка: Поехали

После «Принимаю»:
  аккаунт как при входе через VK/Telegram (identity = max_user_id),
  ссылка с токеном → на сайте УЖЕ вошёл, без второй галочки и без email.
  Помощник видит brief.

Если человек сначала принял галочку на САЙТЕ — в боте не спрашиваем
ещё раз (склеили аккаунт). Документы обновили — тогда коротко ещё раз.

В базу: кто, канал, id, время, версии документов.
«Стоп» всегда. Блок чата = не пишем. Отзыв ПД — на почту.


3. Продажник (тон)
------------------
Не анкета и не «ну как, открылось».
Как человек, который помогает сделать подарок, который ставят в машине.

Фишки потихоньку:
  • Картинка, не функция. Не «ИИ напишет трек», а «человеку, которому
    словами неудобно».
  • Один вопрос. Следующий — только после ответа.
  • Дожать мягко: черновик держим, не «вы не завершили заказ».
  • Помощник на сайте уже в курсе — человек не рассказывает дважды.
  • После пользы — праздники, редко, по календарю, без «только сегодня».

После «Принимаю»:

  «Кому первую песню? Жмите кнопку — или напишите своими словами.»

  Кнопки: Маме / Любимой / Любимому / Другу / Себе / Пока смотрю
  (если пишет своими словами, идём за ним.)

Он: «маме»

  «Тепло или с характером? Можно оба — лишь бы она узнала себя
  с первой строки.»

Он: «тепло, что всегда рядом»

  «Держу: мама, тепло, что всегда рядом. Сейчас открою студию —
  одна бесплатная проба, два варианта. Помощнику на сайте уже
  передам, о чём речь, чтобы не начинать с нуля.»

  Кнопка-ссылка на сайт с токеном (см. п.4).

Если затих на 2–4 часа:

  «Черновик на месте. Если отвлеклись — ничего, ссылка живая.»

На следующий день, один раз:

  «Идея никуда не делась. Напишете — открою студию снова.»

Дальше про эту песню молчим.

Праздник (только кто принял рассылку), за неделю:

  «До 8 марта неделя. Если подарок ещё в воздухе — песню как раз
  успеваем, без суеты. Кому думаете?»

Нельзя: огонёчки, «нейросеть воплотит», «спецпредложение»,
ежедневный пинг, притворяться другом с именем «Макс».


4. Связка бот ↔ сайт ↔ помощник
-------------------------------
Сейчас помощник на сайте (consultant.py) глухой: не знает, кто пишет
и что уже сказали в MAX/VK.

Нужна одна карточка человека:

  contact_id          наш uuid
  max_user_id
  vk_user_id
  tg_user_id
  site_user_id        если вошёл на сайте
  consents            что принял и когда
  funnel              этап: gate / talk / sent_to_site / tried / paid
  brief               «маме, тепло, всегда рядом»
  last_channel        max | vk | site

Переход в студию — вход, не регистрация заново:
  https://sozdaipesnu.ru/?m=<короткий_подпись_токен>

  Токен = уже существующий аккаунт. Сайт ставит сессию, как после VK.
  Галочку согласий не показываем. Поле идеи — из brief.
  Помощник читает тот же brief: не спрашивает «а кому песня?».

Обратно:
  если вошёл через VK ID — склеиваем с vk_user_id бота (уже умеем VK).
  MAX-входа на сайте ещё нет: склейка через токен в ссылке.
  Позже — вход MAX, если появится.

Когда трек готов / оплата прошла — пишем в ТОТ канал, откуда пришёл,
в ту же карточку. Не второй слепой чат.

Помощник на сайте и бот — один тон, одна память, разные окна.


5. GitHub / скилы
-----------------
Готового «скила продажника песен для MAX+VK» нет.
B2B-SDR агенты (outreach, LinkedIn) — не наш случай, не брать.

Что взять как образец устройства, не как чужой тон:
  • карточка человека + этапы воронки + память
    (паттерн IDENTITY / SOUL у агентов)
  • chatman-media/sales — маршрутизация этапов, не тексты
  • наш consultant.py — уже «мозг» сайта; его же кормить brief

Конструкторы Salebot / Senler удобны для ВК-рассылок, но память
с нашим помощником тогда разъедется. Для нас правильнее свой
тонкий бот на нашем сервере.

Маркетинг (воронка, дожим, календарь поводов, что не делать):
  docs/instrukcii/МЕССЕНДЖЕРЫ-МАРКЕТИНГ.txt
  Код не пилим. Сначала бумага и живые формулировки людей.


6. Порядок, когда скажете делать
--------------------------------
1. Карточка контакта + лог согласий (без этого нельзя писать).
2. MAX-бот: ворота → разговор → ссылка с токеном → сайт знает brief.
3. Помощник на сайте читает brief из сессии.
4. VK-сообщество тем же мозгом.
5. Напоминания только по согласию, редко, с «стоп».

Оплата по-прежнему GetPlatinum на сайте.
Генерация по-прежнему у нас (MAX/VK нагрузку генерации не снимают).
